# Loore: методы, формы ответов и грабли

Справочник по источнику данных. Открывай, когда нужно понять, откуда берётся
конкретное поле, почему запрос вернул пустоту или сколько это стоит.

Официальные ресурсы: https://docs.loore.ai – документация и контракт API,
https://app.loore.ai – кабинет и ключи (Настройки → API и MCP).

## Аутентификация и базовый адрес

Каждый метод – `POST https://mcp.loore.ai/v1/<метод>` с JSON-телом и заголовком
`Authorization: Bearer $LOORE_API_KEY`. Тот же набор доступен агенту по MCP:
`https://mcp.loore.ai/mcp`, инструмент `ig_profile` – это REST `/v1/ig-profile`.

```bash
export LOORE_API_KEY="..."     # app.loore.ai → Настройки → API и MCP

curl -s https://mcp.loore.ai/v1/ig-profile \
  -H "Authorization: Bearer $LOORE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"username": "example"}'
```

Скрипты ходят через `scripts/loore.py` (`call()`, `paginate()`, `LooreError`)
и `scripts/loore_ig.py` (лимит частоты, счётчик кредитов, нормализация полей).
Базовый адрес переопределяется переменной `LOORE_API_BASE`.

Ключ – секрет. Только через переменные окружения, никогда в коде, в логах и в
отчётах.

## Одобрение расхода

Платные методы требуют одобрения расхода человеком. Для прогона создаётся
бюджет на весь поток один раз – человек называет общий потолок в кредитах:

```bash
python3 scripts/loore.py approve --flow reels-analytics-for-brokers --cap 3000
export LOORE_SPEND_AUTHORIZATION_ID=<выведенный id>
```

Клиент сам подставляет `spend_authorization_id` в каждый платный вызов. Без него
(или когда потолок исчерпан) Loore отвечает `428 needs_user_confirmation`, а в
`details.suggestedFlowCapCredits` предлагает потолок – скрипт останавливается и
печатает подсказку, что делать.

## Что стоит денег, а что нет

Каждый ответ сообщает фактическую цену вызова в `creditsChargedMilli` (тысячные
доли кредита). Скрипты складывают её и пишут в `seed_stats.json` и
`qualify_stats.json` поле `credits_charged` – это честная стоимость прогона.
Тарифы и цена кредита – на https://loore.ai.

Цены, которые прямо указаны в контракте методов:

| Метод | Цена |
|---|---|
| `ig-profile` | 1 кредит за аккаунт |
| `ig-following`, `ig-followers`, `ig-hashtag-media`, `ig-search` | 1 кредит за каждый внешний запрос, который нужен странице |
| `ig-download` | 0,5 кредита за доставленный файл; приватный, недоступный или слишком большой не списывается |
| `video-transcribe` | 3 кредита за вызов, ролик до 10 минут; ролик длиннее отклоняется без списания |

Для `ig-user-reels`, `ig-media` и `ig-media-comments` цена в описании метода не
указана – смотри `creditsChargedMilli` в ответе.

Главный вывод для пайплайна прежний: **платится не за поле, а за вызов.**

| Данные | Приходят | Отдельный вызов? |
|---|---|---|
| Юзернейм, id, имя профиля, приватность | в строке страницы подписок/подписчиков (`fields: "extended"` добавляет имя) | **нет – в составе страницы списка** |
| Описание профиля (био), категория, число подписчиков | только из `ig-profile` | **да, 1 кредит на аккаунт** |
| Рилсы аккаунта | `ig-user-reels`, до 50 строк на страницу (с подписями ~15-30) | да |
| Комментарии | `ig-media-comments`, до 50 на страницу | да |

На этой асимметрии и построен весь выигрыш скилла: список отдаёт имя в составе
страницы, описание – по кредиту за аккаунт, поэтому грубый отсев делается по
имени, а описание запрашивается только для выживших.

## Методы, которые использует скилл

| Метод | Скрипт | Зачем в пайплайне |
|---|---|---|
| `ig-following` (`username`/`user_id`, `fields: "extended"`, `limit`, `cursor`) | `seed_pool.py` | снежный ком: на кого подписан конкурент |
| `ig-followers` (то же) | `seed_pool.py` | подписчики эталонного аккаунта |
| `ig-hashtag-media` (`hashtag`, `rank: "recent"`) | `seed_pool.py` | свежие публикации под хэштегом |
| `ig-search` (`kind: "reels"` / `"accounts"`, `query`) | `seed_pool.py` | поиск рилсов и аккаунтов по запросу |
| `ig-profile` (`user_id` или `username`) | `qualify_accounts.py` | био, категория, подписчики, приватность, числовой `id` |
| `ig-user-reels` (`user_id`, `limit: 50`, `include_caption: true`) | `qualify_accounts.py` | рилсы аккаунта с метриками и подписью |
| `ig-media` (`media_url_or_code`) | `teardown_reel.sh` | метаданные ролика и вся подпись |
| `ig-download` (`url`) | `teardown_reel.sh` | файл видео |
| `ig-media-comments` (`media_id`, `limit: 50`) | `teardown_reel.sh` | комментарии – там ищется отклик на кодовое слово |
| `video-transcribe` (`url`) | `teardown_reel.sh`, по `LOORE_TRANSCRIBE=1` | транскрипт вместо Groq |
| `spend-authorization` (`action: "create"`) | `loore.py approve` | бюджет расхода на прогон |

Обращаться по числовому `id` дешевле, чем по юзернейму: `user_id` пропускает
поиск аккаунта по имени. Юзернеймы меняются, идентификаторы – нет. Поэтому `id`
сохраняется в пуле и в `accounts.json` под ключом `pk`.

## Формы ответов

Ответ – конверт `{"status": "ok", "result": {...}}` или
`{"status": "error", "error": "...", "details": {...}}`. Поля внутри `result`
описаны в контракте и имеют одно имя на всех методах.

Соответствие полей Loore полям файлов скилла (`media_fields()` в
`scripts/loore_ig.py`):

| Файл скилла | Loore | Примечание |
|---|---|---|
| `pk` (ролик) | `id` | числовой id, ключ для комментариев |
| `code` | `code` | шорткод; ссылка `https://www.instagram.com/reel/{code}/` |
| `views` | `views` | отсутствует, если Loore не получил положительного счётчика – тогда 0 |
| `likes` | `likes` | отсутствует при `likesHidden: true` – тогда 0 |
| `comments` | `comments` | |
| `duration` | `durationSec` | |
| `taken_at` | `takenAt` | ISO-8601 → секунды unix |
| `caption` | `caption` | в списке – до 500 символов, в `ig-media` – целиком |
| `is_pinned`, `is_trial` | `isPinned`, `isTrial` | такие ролики не входят в медиану аккаунта |

Поля профиля: `id` → `pk`, `fullName` → `full_name`, `followers` →
`followers`, `biography`, `category`, `isPrivate`.

## Пагинация

Списки отдают `items`, `hasMore` и `nextCursor`; курсор передаётся обратно
параметром `cursor`. `limit` – до 50, больше отклоняется, а не обрезается.
Курсор живёт 6 часов и привязан к тому же аккаунту: продолжать можно тем же
`username` или `accountId` из первого ответа – `paginate()` в
`scripts/loore_ig.py` переходит на `user_id` со второй страницы. Он же
останавливается на повторяющемся курсоре и после второй пустой страницы
подряд.

## Коды ошибок

| Код | Что значит | Что делает скрипт |
|---|---|---|
| 401 | ключ не принят | стоп с подсказкой |
| 402 | закончились кредиты или квота тарифа | стоп |
| 403 | нет прав на метод или аккаунт приватный | пропуск этого аккаунта |
| 404 | не найдено | «нет данных», не ошибка |
| 428 | нужно одобрение расхода | стоп, подсказка про `loore.py approve` |
| 429 | исчерпан бюджет запросов | пауза по `details.retry_after_seconds`, повтор |
| 502 | метод не реализован | стоп |
| 503 | сбой источника | повтор с откатом |

## Грабли

**Закреплённые рилсы идут первыми.** Лента рилсов начинается с закреплённых
(`isPinned`), хронология сломана. Нельзя останавливать пагинацию на первом
«старом» ролике – так теряется всё, что за ним. Читай фиксированное число
страниц и фильтруй по времени публикации после.

**Просмотры иногда отсутствуют.** Loore не отдаёт `views`, когда ни один счётчик
не положителен: ноль нельзя отличить от «не посчитали». Такие ролики
отбрасываются из медианы, иначе они утащат её вниз и создадут фальшивые
всплески у соседей.

**Пробные рилсы.** `isTrial: true` – ролик показан только неподписчикам, его
цифры описывают другую аудиторию. Из медианы аккаунта он исключается.

**Ссылки на файл подписанные и живут минуты.** `downloadUrl` из `ig-download`
работает около 15 минут. Хранить её бессмысленно и вредно; `loore_ig.py`
скачивает файл сразу и ссылку на диск не пишет.

**Приватные и удалённые аккаунты.** `ig-profile` отвечает и для приватного
(`isPrivate: true`), такие отсеиваются до запроса рилсов. Удалённый аккаунт –
404, клиент возвращает `{}`, прогон не падает.

**Строки хэштегов и поиска рилсов.** В них только юзернейм автора (`author`),
без id и имени. Такой автор попадает в пул с ключом `handle:<юзернейм>` и
получает числовой id на квалификации.

**429.** Транзиентный. Клиент ждёт `retry_after_seconds` и повторяет; если 429
идут часто – уменьшай `--rps` и `--workers`.

## Чего в API нет

Важно знать до того, как пообещаешь результат:

- **охваты, досматриваемость, удержание, переходы по ссылке** – это данные
  кабинета владельца аккаунта, наружу они не отдаются никем. Просмотры ≠ охват;
- **личные сообщения и заявки** – сколько людей написало кодовое слово в личку,
  снаружи не видно. Видно только след в комментариях, и это нижняя оценка;
- **био и число подписчиков в списках** – строки подписок, подписчиков и поиска
  не несут описания профиля и счётчиков; они есть только в `ig-profile`, по
  одному аккаунту. Искать по тексту био нельзя, поэтому фильтр по имени – не
  оптимизация, а единственный доступный путь;
- **история метрик** – API отдаёт срез на сегодня. Динамика получается только
  собственными регулярными срезами. Это и есть причина, по которой скилл
  устроен как радар, а не как разовый отчёт;
- **демография аудитории** – пол, возраст, гео подписчиков недоступны.
